# 地形を読む

圃場の地形を数字と図にして、「冷気がどこを流れ、どこに溜まるか」「この斜面はブドウに向くか」を判断する。凍害・霜害は、晴れて風の弱い夜に地面近くで冷えた空気が低い所へ流れ、出口をふさがれた所に溜まって起きやすい。だから一番大事なのは冷気の流れと溜まり場で、斜面の向きは最後に効く要素として見る。

## 本家

- 名前：skills-for-agriculture の `s4ag-land-reading`（Finn Fitzsimons、MIT ライセンス）
- 原文：https://github.com/human-avatar/skills-for-agriculture/blob/main/skills/s4ag-land-reading/SKILL.md
- 中身：歩いて観察して土地を読む手順。傾斜の区分、斜面の向き、キーライン（斜面が凸から凹に変わる線）、尾根・中腹・谷底の違い、霜穴（冷気が溜まる窪地）の見つけ方。途中のチェックポイントで前提（どちらの半球か、気候はどうか）を確かめてから進む

## 本家の読み方

1. `skills-for-agriculture:s4ag-land-reading` が入っていれば、それを呼んで手順に従う
2. 入っていなければ、上の原文を開いて読み、その手順に従う（毎回読むので、本家が更新されれば新しい版が使われる）
3. 原文が開けなければ、その旨を伝えて止まる。下の調整だけで進めない

本家は現地を歩く観察が中心。こちらはそれを標高データの計算で裏付け、ワイン用ブドウの目安で判断する。日本は北半球なので、南向きが暖かい側になる。

## 0. 設定を読む

🧭 AI設定ページから読む。無いものは利用者に聞く。

| 設定 | 使い道 |
| --- | --- |
| 圃場の位置（緯度経度を1点） | 標高データと写真を取る中心 |
| 区画図の置き場 | 区画の名前を地図に重ねる |
| 気温の記録（接続表の温度ログ、あれば） | 地形の見立てを実際の冷え方で確かめる |
| 被害の記録（凍害・霜害の出た区画、あれば） | 原因調査のときに地形と並べる |

## 1. 何のために読むかを決める

- **原因調査**：被害が出た所と出なかった所の差を、地形で説明できるかを見る
- **土地選び**：候補地どうし、または候補地の中の場所どうしを比べる

どちらかで、まとめ方（7）が変わる。

## 2. データを取る

| データ | 国土地理院のタイル名 | 間隔 | 標高の精度（標準偏差） |
| --- | --- | --- | --- |
| 5mメッシュ（航空レーザー） | `dem5a` | 約5m | 0.3m以内 |
| 5mメッシュ（写真測量） | `dem5b` | 約5m | 0.7m以内 |
| 5mメッシュ（写真測量・島嶼部など） | `dem5c` | 約5m | 1.4m以内 |
| 10mメッシュ（地形図の等高線から） | `dem10b` | 約10m | 5m以内 |
| 航空写真（全国最新） | `seamlessphoto` | — | — |

5mメッシュは場所によって種類が違う。`dem5a` → `dem5b` → `dem5c` の順に探し、どれも無ければ `dem10b` を使う。どれを使ったかは必ず結果に書く（`dem10b` では数mの段差や小さな窪地は見えない）。

### 取り方

クラウドのシェルや手元のパソコンのシェルからは、国土地理院のサイトに届かないことがある（プロキシで断られる）。そのときはブラウザ（Claude in Chrome など）で取る。

1. 新しいタブで **HTMLのページ**を開く（例：`https://maps.gsi.go.jp/development/ichiran.html`）。タイルの `.txt` を直接開いたページは、スクリーンショットが撮れないので作業場所にしない
2. このスキルの `scripts/gsi-terrain.js` の中身を `javascript_tool` で実行する。`window.GT` に関数が入る（国土地理院のタイルは別のページからも読める）
3. 次のように取る

```js
const dem = await GT.loadDem(緯度, 経度);          // 中心の周り3×3タイル（5mなら約2.7km四方）
const [cj, ci] = dem.center;
const c = GT.crop(dem, cj, ci, 110);               // 中心から±110マス（5mなら約±380m）
const F = GT.fill(c.d), acc = GT.flowAcc(c.d, F);
const photo = await GT.loadPhoto(c);
`${dem.sources.map(s => s.kind).join(',')} / 1マス ${c.px.toFixed(2)}m`;
```

### 結果の受け渡し

- **数字**は `javascript_tool` の戻り値で受け取る。地点ごとの要約（4の `describe`）や断面など、小さくまとめてから返す。標高の格子をまるごと文字で受け渡さない（大きすぎるうえ、写し間違える）
- **図**は `GT.render` で描き、`GT.show` でページに表示して、スクリーンショットを `save_to_disk` で保存する。区画を読むときは、10マスごとの方眼を入れた写真を表示すると、格子の座標が読み取れる
- **Notionに図を貼る**ときは、`notion-create-file-upload` で受け取ったURLへ、ブラウザから `fetch` で canvas の画像を送る（クラウドからは Notion のアップロード先に届かないことがある）

## 3. 区画を重ねる

区画図と航空写真を、畑の形・道路・池・林の切れ目で見比べて、区画が格子のどこにあるかを決める。目で合わせるので、**どこを何と読んだかを結果に書き、利用者に確かめてもらう**。特に被害の大きい区画は、名前と場所が合っているかを先に確かめる。

航空写真は撮影がブドウを植える前のことがある。造成で地形を変えた所は、標高データも写真も今と違う。

## 4. 計算する

区画ごと（大きな区画は上・中・下）に地点を置き、`GT.describe(c, F, acc, { 名前: [j, i] })` で次を出す。地点は切り出した範囲の端から90m以上内側に置く（端に近いと周りとの比較がゆがむ）。

| 項目 | 意味 |
| --- | --- |
| `elevation` | 標高（m） |
| `slopePercent` | 傾斜（%）。8.7%≒5°、15%≒8.5° |
| `aspect` | 斜面の向き（下る方位。北0°・東90°・南180°・西270°） |
| `tpi35`・`tpi90` | 半径35m・90mの平均との差（m）。マイナスなら周りより低い |
| `pondDepth` | 周りを囲まれた窪地の深さ（m）。0より大きければ、冷気も水も出口が無い |
| `upslopeArea_m2` | その地点に流れ込む上流の面積（m²）。大きいほど冷気が集まってくる |

加えて、断面を `GT.profile(c, [j1, i1], [j2, i2], 5)` で取る。

- 斜面の上 → 被害の出た所 → その下流、の向き。下流側が高ければ、出口がふさがれている
- 段々の畑を横切る向き。段の高さと、段の上が平らかどうかが分かる

## 5. 読み方（ワイン用ブドウの目安）

| 要素 | 見るもの | 目安 |
| --- | --- | --- |
| 冷気の溜まり場（一番大事） | `pondDepth`・`tpi` がマイナス、断面で下流側が高い、平地が斜面の裾にある | 低い所に冷えた空気が溜まり、霜・凍害の危険がずっと高い。木や土手は冷気の流れを止める |
| 周りとの高さ | `tpi90`、断面 | 周りより高い所ほど冷気が抜ける。ただし地域として標高が高すぎる・低すぎる不利は、周りより高いことでは補えない |
| 傾斜 | `slopePercent` | 緩い〜中くらいの傾斜が良い（冷気が抜ける）。約15%を超えると機械の横転・浸食のおそれ。0〜2%の平地は冷気が淀みやすい |
| 斜面の向き | `aspect` | 要素の中で一番弱い。北向き：萌芽が遅く、冬の最低気温が低く、生育期間が短い。南向き：萌芽が早く、冬の最低気温が高く、生育期間が長い。東向き：萌芽が遅く、朝に葉が早く乾く。西向き：萌芽が早く、朝に葉が乾くのが遅い。南・西向きは北・東向きより萌芽が最大7日ほど早まり、晩霜の危険が上がる |
| 冷涼な地域での向き | `aspect` | 夏が涼しく積算温度が少ない地域では、北向きを避け、南（南東〜南西）を選ぶ。東向きは朝日で葉が乾き、午後の強い日差しを避けられる。西向きは遅く熟す品種に向く |
| 積雪地の冬（北海道など） | 現地の積雪の記録、地形 | −20℃を下回ると凍害を受けるので、冬は積雪で守る必要がある。晩霜・初霜、開花期の低温、いつも強い風が吹く場所を避ける |

### 根拠のない見立て（現地で確かめる）

次は文献の目安ではなく、地形から考えられることとして書く。結論に使うときは、気温や積雪の記録で確かめてからにする。

- 列が冷気の流れる向きと直交していると、列と下草が冷気の抜けをじゃまし、地面近くに薄い層が残るかもしれない
- 風が当たる尾根や凸の所は雪が飛んで少なくなり、凍害を受けやすいかもしれない。吹きだまりや除雪の雪山は、冬の冷気の流れる道を変えるかもしれない
- 平らな段の上は、水が抜けにくく、登熟の遅れにつながるかもしれない

## 6. 確かめる（地形の見立てを気温で）

地形で「溜まる」「抜ける」と読んだ所に温度計を置き、実際の冷え方で確かめる。

- 基準点は、周りから冷気が流れ込まない平らな所か高い所に置く
- 置く前に全台を1か所に並べて1〜2晩測り、個体差を出す
- 高さはそろえる（例：果房の高さ）。地面近くの薄い冷気の層を疑う場所は、低い所（例：30cm）にも置き、基準点でも同じ高さの組を作る
- 比べるのは、晴れて風の弱い夜の最低気温。日よけの無い温度計は日中に日が当たると温まるので、昼の値は比べない
- 雪が積もった後は雪面からの高さが効くので、積雪深も記録する

## 7. まとめ方

人が読むので `core:writing-for-humans` に従う。

1. **結論**：どこに冷気が溜まり、どこは抜けるか（土地選びなら、どこが向くか）を最初の2〜3文で
2. **図**：航空写真＋等高線＋区画名＋冷気の流れる向き（矢印）。縮尺と方位を入れる
3. **区画ごとの表**：標高、傾斜、向き、周りとの差、窪地の深さ
4. **断面**：出口がふさがれている所、段の高さ
5. **注意**：使った標高データの種類と精度、データの時期（造成前かどうか）、区画は目で合わせたこと
6. **次に確かめること**：温度計の置き場所、現地で見ること

原因調査なら、地形で説明できる差と、説明できない差（品種・剪定・土・水はけなど、地形以外を疑うもの）を分けて書く。
